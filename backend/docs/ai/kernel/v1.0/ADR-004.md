# ADR-004: AI Core Kernel Architecture

## Status
**APPROVED & FINALIZED** (Baseline Release v1.0.0)

## Context
Menyusul keberhasilan seluruh implementasi Era-1 (Foundation), dari Platform, Knowledge, Cognitive, Service Mesh, hingga Event Platform, TeamTender kini harus mensahkan 5 lapis struktur itu menjadi sebuah Kernel *Immutable*.
Batas absolut (*Boundary*) harus diluruskan agar Plugin tak mampu mengimpor secara destruktif, dan pergerakan Kernel tetap mengikuti kaidah deterministik.

## Decision
- **Strict Boundary (Kernel vs API)**: Memisahkan 100% rute perantara di `backend/src/ai/api` (berisi *Gateway*, SDK) dari `backend/src/ai/kernel` (lapisan tertutup).
- **Unified Runtime Registry**: Transisi dari statis menjadi *Manifest-Driven* (Capability, Event, Tool). Registri dibaca dan disimpan sementara di *Cache/Memory*.
- **Abstraksi Storage**: Memaksakan abstraksi murni (`IEventStore`, `IEventBus`) bagi transportasi dan persistensi AI.
- **Kernel Boot Sequence**: Sistem AI akan memiliki Lifecycle eksklusif (`CREATED -> INITIALIZING -> READY -> DEGRADED -> STOPPING -> STOPPED`) melalui komponen `AIKernelBootSequence`.

## Consequences
**Keunggulan Utama**: 
Kernel mencapai *Zero Vendor Lock-in*. Kemudahan pergeseran penyimpanan dari memori statis ke basis data SQL ataupun MQ terpusat. Keandalan eksekusi Plugin yang dijaga lapis Gateway.

**Batas dan Regulasi**:
Perubahan apapun pada lapisan yang telah disahkan ini akan memicu perombakan `MAJOR` dan memerlukan konsensus tingkat eksekutif melalui perantara `RFC-001`.
