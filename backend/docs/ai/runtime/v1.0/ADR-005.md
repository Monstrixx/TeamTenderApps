# ADR-005: Retrieval Platform Architecture

## Status
**APPROVED** (Implementation Era-2)

## Context
Menjelang integrasi *Agent Runtime* dan Copilot lintas-domain, AI TeamTender membutuhkan lapisan penyuplai wawasan. Mengizinkan AI untuk langsung memanggil fungsi `vectorStore.similaritySearch()` akan berujung pada kekacauan kebijakan akses, pemborosan biaya LLM (*Cost-Inefficiency*), dan halusinasi fatal (kekurangan validasi).

## Decision
- **Pemusatan Tanggung Jawab (Knowledge Access Layer)**: Mengubah nama dan peran *Retrieval Platform* dari "Fasilitas Pencarian" menjadi "Penyedia Pengetahuan" mutlak.
- **Objek Imutabel (`KnowledgePackage`)**: Konklusi akhir pelacakan bukanlah `Result[]`, melainkan `KnowledgePackage` ter-enkripsi (*hashed*, memiliki usia (*expiration*), dan riwayat penyusunan) yang akan dikonsumsi LLM secara eksklusif.
- **Pipeline RRF Terstruktur**: Penarikan informasi dimandatkan melewati 11 tahap kaku: `Query Understanding -> Expansion -> Planner -> Cache -> Execution -> Fusion (RRF) -> Evidence Scoring -> Context Building -> Packaged`.
- **Cost-Based Query Planner**: Planner akan bertindak seperti perencana kueri basis data modern (RDBMS Planner). Planner menimbang latensi, biaya kognitif (API Cost), dan ketersediaan mesin sebelum memutuskan rute (*Vector, Graph, Keyword*).

## Consequences
- Kecepatan latensi (tanpa LLM) ditargetkan keras `<200ms`.
- Terwujudnya konsep "AI tidak pernah mengonsumsi data mentah, melainkan hanya mengonsumsi **KnowledgePackage**".
- Kompatibilitas luas lintas-penyedia (*Provider-Agnostic*): Dukungan penuh untuk *pgvector, Pinecone, Neo4j, Elasticsearch*, dsb., berkat abstraksi antarmuka (Tanpa perlu mengubah *Planner*).
